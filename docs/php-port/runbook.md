# เมื่อเว็บมีปัญหา

อ่านทีละข้อ ทำตามลำดับ อย่าแก้หลายจุดพร้อมกัน

ไฟล์ลับอยู่ที่ `foundu/config/.env.php` สิทธิ์ต้องเป็น 600 ตลอด อย่าส่งไฟล์นี้ในแชท

## เว็บเปิดไม่ขึ้น

1. เปิดโดเมนในเบราว์เซอร์ ถ้าขึ้นหน้า Cloudflare สีส้ม ปัญหาอยู่ที่ Cloudflare หรือต้นทางไม่ตอบ
2. เข้า DirectAdmin ดูว่าโดเมนยังชี้มาที่โฮสต์ และใบรับรองยังไม่หมดอายุ
3. เปิด File Manager ดูว่า `public_html/index.html` และ `public_html/api/index.php` ยังอยู่
4. เปิด Error Log ของโดเมนใน DirectAdmin อ่านบรรทัดล่าสุด ถ้าขึ้นว่า PHP ต่ำกว่า 8.2.36 ให้ไปที่ Select PHP Version แล้วเลือก 8.3 หรือ 8.4
5. ถ้าเพิ่งอัปโหลด zip ใหม่ ให้ล้างแคชที่ Cloudflare (Purge Everything) แล้วลองใหม่
6. ถ้าขึ้น 403 ทั้งเว็บ ให้อ่านหัวข้อ REMOTE_ADDR ใน `cloudflare.md` ก่อน จะได้ไม่ไปแก้จุดอื่น

## กำลังถูกโจมตี

1. ที่ Cloudflare เปิดกฎหมายเลข 5 (Managed Challenge) ที่ปิดไว้อยู่ รายละเอียดอยู่ใน `cloudflare.md`
2. ถ้ายังถล่มอยู่ เปิด Under Attack Mode ที่ภาพรวมของโดเมน ผู้ใช้จริงจะต้องติ๊กถูกก่อนเข้าเว็บ เปิดไว้ชั่วคราว
3. Bot Fight Mode เปิดได้ตอนนี้ แต่ `/api` อาจพังกับผู้ใช้จริง พอสถานการณ์สงบให้ปิดกลับ
4. อย่าไปลบไฟล์ใน `foundu/` ตอนนี้ ตัวจำกัดจำนวนคำขออยู่ใน PHP อยู่แล้ว

## หมุนคีย์

แก้ใน `.env.php` อย่างเดียว แล้วบันทึก สิทธิ์ยังเป็น 600

| อยากเปลี่ยน | แก้ค่าไหน | ผลที่เกิดขึ้น |
|---|---|---|
| คีย์เซสชัน | `APP_KEY` สุ่มข้อความยาวใหม่ | ผู้ใช้ทุกคนหลุดล็อกอิน ต้องเข้าใหม่ |
| คีย์เข้ารหัส | `DATA_KEY` และ `LOOKUP_KEY` | ของที่เข้ารหัสไว้แล้วอ่านไม่ได้ อย่าเปลี่ยนถ้าไม่รู้ว่ากำลังทำอะไร |
| R2 | `R2_ACCESS_KEY_ID` และ `R2_SECRET_ACCESS_KEY` ที่ Cloudflare แล้วคัดลอกมา | อัปโหลดรูปใหม่ใช้คีย์ใหม่ ของเก่ายังอยู่ถ้าบัคเก็ตเดิม |
| Turnstile | สร้าง widget ใหม่ ใส่ `TURNSTILE_SITE_KEY` และ `TURNSTILE_SECRET` | ปุ่มยืนยันตัวตนใช้คีย์ใหม่ทันที |
| AI | `GEMINI_API_KEY` หรือ `OPENROUTER_API_KEY` | แชทใช้คีย์ใหม่ ถ้าเว้นว่าง แชทจะบอกว่ายังไม่ได้ตั้งคีย์ |

หลังเปลี่ยนคีย์ AI หรือ Turnstile ให้ลองล็อกอินและส่งแชทหนึ่งข้อความ

## กู้จากแบ็กอัป

แบ็กอัปเป็นไฟล์ `foundu-YYYYMMDD.sql.gz` ในบัคเก็ต R2 โฟลเดอร์ `backups/` cron อัปขึ้นให้ทุกวัน

1. ดาวน์โหลดไฟล์ล่าสุดจาก R2
2. บนเครื่องที่มี PHP CLI และต่อฐานข้อมูลได้ รัน

```bash
php foundu/bin/restore.php foundu-YYYYMMDD.sql.gz
```

สคริปต์นี้ไม่เรียก `exec()` มันแตก gzip เองแล้วใส่ทีละคำสั่ง บนโฮสต์ที่ไม่มี SSH ให้แตกไฟล์เป็น `.sql` บนเครื่องตัวเอง แล้วใน phpMyAdmin เลือกฐานข้อมูล แล้ว Import ไฟล์ `.sql` อย่านำเข้าทับฐานข้อมูลผิดตัว

3. ตรวจว่าแถวใน `accounts` กลับมา แล้วลองล็อกอินบัญชีที่รู้จัก

การกู้ทับข้อมูลที่ผู้ใช้เพิ่งโพสต์หลังเวลาแบ็กอัป โพสต์นั้นจะหาย บอกผู้ใช้ก่อนลงมือ

## ปิดรับสมัครชั่วคราว

ใน `.env.php` ตั้ง

```
SIGNUPS_ENABLED=0
```

คนที่ยังไม่มีบัญชีจะสมัครไม่ได้ ข้อความบนหน้าเว็บคือ `ปิดรับสมัครชั่วคราว` คนที่มีบัญชีแล้วยังล็อกอินได้ ผู้ดูแลยังเพิ่มนักเรียนจากหน้าแอดมินได้ เปิดกลับโดยตั้งเป็น `1`

## ดูสถานะ

ผู้ดูแลเปิดแผงผู้ดูแล แล้วเลือก สถานะระบบ หน้านี้บอก PHP ฐานข้อมูล ครั้งล่าสุดที่ cron รัน แบ็กอัปขึ้น R2 แล้วหรือยัง และว่าตั้ง Turnstile, AI, R2 ไว้หรือยัง ไม่แสดงค่าคีย์ ปุ่มรันไมเกรชันใช้เมื่อมีไฟล์ใหม่หลังอัปเดต แต่ละครั้งไม่เกิน 30 วินาที

## อ่านล็อกใน DirectAdmin

- **Error Log** ของโดเมน คือข้อความจาก Apache และ PHP ที่ล้มตอนบูต
- ไฟล์ `foundu/storage/logs/app.log` คือล็อกของแอป (Monolog) เปิดด้วย File Manager
- ตาราง `error_logs` ใน phpMyAdmin คือข้อผิดพลาด 5xx ที่แอปจับได้ มีข้อความ ไม่มีรหัสผ่าน
- ตาราง `login_attempts` ดูความพยายามล็อกอินที่ผิด บัญชีถูกล็อก 15 นาทีหลังผิด 5 ครั้ง
